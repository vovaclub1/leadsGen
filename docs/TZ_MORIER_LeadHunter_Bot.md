# ТЗ: MORIER LeadHunter — Telegram-бот поиска и распределения клиентов

Версия 1.2 · сентябрь 2026 · заказчик: MORIER (Telegram-агентство посевов, RU-рынок)

---

## 0. Суть за 60 секунд

**Что строим.** Telegram-бот, который сам находит рекламодателей с бюджетом, изучает их с помощью ИИ, кладёт готовую карточку лида в очередь команды, отдаёт лид первому нажавшему младшему менеджеру (SDR), контролирует, чтобы клиенту написали в срок, ведёт касания по каденции и передаёт тёплого клиента старшему. Дисциплина держится на **рейтинге и естественных последствиях**, а не на штрафах. Каждый исход лида становится обучающим примером — бот с каждым месяцем находит и оценивает лидов точнее.

**Что НЕ строим.**
- Бот **не пишет клиентам сам**. Пишет человек. Автоспам с аккаунта = бан аккаунта и смерть главного отличия MORIER — персонализации.
- Никаких денежных штрафов и никакого «баланса в рублях» внутри бота. Деньги считаются по марже вне бота, как записано в политике оплаты.
- Никакого локального ИИ на сервере. 1 vCPU / 2 GB — только API.

**Почему это выстрелит.** Самые тёплые лиды по вашей же SDR-инструкции — «кто уже покупает рекламу у конкурентов». Сейчас SDR ищет их руками. Бот будет читать 100–300 гейминг-каналов в реальном времени, ловить каждый рекламный пост, вытаскивать рекламодателя, изучать его и через минуту выкладывать карточку с готовым персонализированным фактом для первого сообщения. SDR остаётся только написать.

## 2. Честные ограничения и принятые решения

### 2.1 Trustat бесплатный — не источник лидов, а инструмент проверки
Факт (скриншоты владельца): API Stat — 5 каналов, 50 запросов/мес; API Search — 2 ключевых слова, 100 запросов/мес; 2 rps; глубина 3 дня. Это ~3 запроса в день.

**Решение.** Trustat используется для:
1. Отладки интеграции (модуль источников данных сразу проектируется «под несколько поставщиков»: Trustat, MTProto, позже TGStat).
2. Точечной проверки перед передачей старшему: `quality_score`, ER, динамика подписчиков лида — 50 запросов/мес на это хватает.
3. На платном тарифе (Medium — 249 ₽/мес по данным на сентябрь 2026, лимиты уточнить командой `/subscription` в @trustat) — доступ к **базе Telegram Ads**: рекламодатели, которые уже покупают официальную рекламу в Telegram. Это лиды с подтверждённым бюджетом.

Основной бесплатный и безлимитный источник — **MTProto** (см. 4.1).

### 2.1a Пул API-ключей (в т.ч. бесплатные ключи с аккаунтов друзей)
Решение владельца: подключать несколько бесплатных ключей Trustat и переключаться, когда лимит исчерпан.

**Честная оценка до проектирования.**
- Все запросы уходят с одного IP сервера. Пять бесплатных ключей с одного адреса Trustat увидит без усилий; при бане теряются все ключи и, вероятно, Trustat-аккаунты друзей. Прокси под каждый ключ в ТЗ не закладывается — это уже осознанный обход правил сервиса.
- Экономия — стоимость тарифа Medium, 249 ₽/мес.
- Реальный выигрыш не в запросах Stat (5 ключей × 50 = 250/мес — на проверку перед передачей хватает и одного), а в **ключевых словах Search**: 2 слова на ключ → 10 слов на пять ключей.
- Каждый друг должен сам активировать бесплатный тариф в @trustat и передать ключ, понимая риск.

**Рекомендация:** пул строим в любом случае (он нужен для платный + бесплатный, для TGStat и запасных ИИ-ключей), стартуем на своём ключе + 1–2 друзей для теста, после первого месяца покупаем Medium — бесплатные остаются запасом.

**Как устроен пул.**
- Таблица `api_keys`: поставщик (trustat_stat / trustat_search / tgstat / ai), ключ (шифрованно), чей аккаунт (метка), лимиты день/месяц, израсходовано, дата сброса, статус (активен / исчерпан / забанен / истёк), последняя ошибка, для Search-ключей — закреплённые за ним 2 слова.
- **Маршрутизатор**: перед вызовом выбирает активный ключ с наибольшим остатком месячной квоты; ключ с остатком 0 не пробуется вовсе. Политика «сначала платный / сначала бесплатные» — настройка владельца.
- Ответ «лимит исчерпан» → ключ помечается исчерпанным до даты сброса, запрос прозрачно уходит на следующий. Ответ 401/403 → ключ помечается забаненным, владельцу уведомление немедленно.
- **Резерв 20 %** квоты пула держится под приоритетные вызовы — проверку перед передачей старшему. Обогащение лидов (score ≥ 60) работает только из оставшихся 80 %.
- Search-ключи не ротируются по запросам — каждое ключевое слово жёстко привязано к своему ключу. Пул здесь умножает слова, а не запросы.
- `/keys` — состояние пула: по каждому ключу остаток, сброс, статус. Уведомление владельцу при остатке пула < 20 % и за 3 дня до предполагаемого исчерпания по текущему темпу.
- Если пул пуст — бот не падает: проверка перед передачей помечается «Trustat недоступен, данные MTProto», и карточка уходит старшему без неё.

### 2.2 Сервер: Windows Server 2022, 1 vCPU, 2 GB DDR5, 30 GB NVMe, Нидерланды
- Для бота, сканера и БД — достаточно, с запасом.
- Для локальных LLM, браузерных скраперов (Selenium/Playwright), тяжёлого ML — нет. Не пытаться.
- Плюс локации: из Нидерландов доступны любые ИИ-API без VPN.
- Пароль Administrator был показан в чате скриншотом — **сменить до начала работ**, включить RDP только с белого списка IP.

### 2.3 «Обучение ИИ на своих данных» — что это значит на практике
Дообучать (fine-tune) большую модель на 200 лидах — бессмысленно и дорого. Реально и дёшево работают три механизма, все заложены в ТЗ (раздел 10):
1. **Разметка исходов** с первого дня: каждое «ответил / не ответил / купил / нецелевой» — обучающий пример.
2. **Few-shot из своей базы**: в промпт ИИ подставляются 10–20 самых похожих уже размеченных лидов. Точность растёт без обучения модели.
3. **Собственная модель скоринга** (scikit-learn), которая переобучается каждую ночь на своих данных и предсказывает вероятность ответа/покупки. Работает на 1 vCPU, стоит 0 ₽.

Fine-tune внешней модели — не раньше 500+ размеченных лидов, и только если пункты 1–3 упёрлись в потолок.

### 2.4 Беттинг и казино — берём, решает старший
Решение владельца: такие лиды не отсеиваются. Как это устроено:
- Стоп-лист (−100, не в очередь) остаётся только для скама, конкурентов-агентств и того, что владелец внесёт руками.
- Появляется **жёлтый список тематик**: беттинг, казино, крипто-«сигналы», 18+. Лид из жёлтого списка идёт в очередь как обычный, но с тегом «Тематика-риск: беттинг» на карточке и без бонуса скоринга за нишу. SDR ведёт как обычно, только вилку цены не называет до проверки старшим.
- При передаче старшему бот прикладывает **матрицу размещаемости**: какие каналы MORIER в вертикалях клиента принимают эту тематику (флаги по каналам — в таблице каналов, раздел 8.1). Старший сразу видит, есть ли куда ставить, а не выясняет это переписк��й с админами.
- ИИ отдельно извлекает признак «лицензированная БК (лицензия ФНС, легальный .ru-домен) / нелицензированное казино». Честно: реклама лицензированных букмекеров в РФ легальна с маркировкой, онлайн-казино — нет, и это риск не только для агентства, но и для каналов. Бот только помечает — решение за старшим.

## 4. Источники лидов

Модуль источников — плагинный: каждый источник отдаёт «сырого кандидата» в единый пайплайн (раздел 5). Источник хранит собственный рейтинг полезности (сколько его кандидатов дошли до ответа/сделки) — на него опирается приоритет сканирования.

### 4.1 Монитор рекламы в донорских каналах (MTProto) — главный источник
**Идея.** Отдельный Telegram-аккаунт («сканер») подписан на 100–300 донорских каналов: все каналы базы MORIER, каналы конкурентов, топ гейминг-каналов по вертикалям (Brawl Stars, CS2, Dota 2, Steam, Roblox, консоли, стриминг). Подписка даёт **живой поток новых постов без опроса** — нагрузка на аккаунт минимальная.

**Детектор рекламного поста** (два уровня):
1. Эвристики (бесплатно, мгновенно): `#реклама`, `Реклама.`, `erid:`, `ИНН`, `О рекламодателе`, `промокод`, ссылка на внешний t.me-канал/бота или сайт, кнопка с URL, «партнёрский пост», характерные CTA. Балльная сумма → порог.
2. ИИ-классификатор (только для спорных, ~20 % постов): «это реклама? кто рекламодатель? что продаёт?» — JSON-ответ. Стоимость ~0,03 ₽ за пост.

**Извлечение рекламодателя.** Из поста берутся все ссылки → нормализуются в сущность: `t.me/username` (канал/бот), домен сайта, бренд (из текста, через ИИ). Если рекламодатель — канал: сканер открывает его профиль (публичный, без вступления), берёт описание, число подписчиков, дату последнего поста, 10 последних постов, ищет контакт («по рекламе @…», «менеджер», «сотрудничество»). Если бот — ищется связанный канал в описании бота. Если сайт — лёгкий HTTP-запрос главной и `/contacts` без браузера, ищутся t.me-ссылки.

**Дополнительные сигналы из этого источника** (сильно повышают скоринг): сколько разных каналов купил этот рекламодатель за 30 дней, в каких вертикалях, как давно последняя покупка. Рекламодатель с 3+ размещениями за месяц — горячий.

**Что ещё забираем из рекламного поста** (бесплатно, уже в руках):
- **Креатив клиента** — ссылка на пост и текст сохраняются в лид. При передаче старшему прикладывается: «у клиента есть готовый креатив — запуск за день».
- **Реальный охват рекламы в донорах** — MTProto отдаёт просмотры поста; сканер перечитывает их через 24 и 48 ч. Получается таблица «канал → реальный охват рекламного поста» по всем донорам, включая конкурентов. Это аргумент в продаже, проверка собственной «гарантии охвата» и данные для закупщика.
- **Кто продал размещение** — если в посте видна метка агентства-конкурента, лид получает флаг «клиент конкурента» (+15 к скорингу): он уже платит за такое, вопрос только кому.

**Защита аккаунта-сканера (обязательно):**
- Отдельный номер, отдельный аккаунт, 2FA. Никогда не личный аккаунт владельца или сотрудника.
- «Прогрев» новой учётки: первые дни — только чтение, вступление ≤ 20 каналов/день.
- Лимиты: ≤ 1 запрос/сек, ≤ 150 разрешений username в сутки, ≤ 300 чтений истории в сутки, случайные паузы.
- Никаких исходящих сообщений с аккаунта-сканера. Вообще.
- При `FloodWait` — уважать задержку, при повторных — стоп на 12 ч и уведомление владельцу.

### 4.2 Поиск по ключевым словам
Ключевые слова по нишам клиентов MORIER: «пополнение Steam», «ключи Steam», «донат Brawl Stars», «гемы», «буст CS2», «скины CS2», «Dota 2 буст», «Robux», «VPN для игр», «игровой магазин», «донат-платформа» и т.д. — управляются владельцем в боте.

Поставщики (по приоритету):
1. **MTProto глобальный поиск** каналов по названию/описанию (бесплатно, лимитированно).
2. **Trustat API Search** — поиск публикаций (на бесплатном — 2 слова и 100 запросов на ключ; с пулом из N ключей — 2N слов, см. 2.1a). Под этот источник — не товарные слова, а **слова спроса на рекламу**: «ищу каналы для рекламы», «куплю рекламу в telegram», «нужен посев», «бюджет на рекламу», «ищем админов каналов». Это рекламодатели, которые сами ищут площадки прямо сейчас, — самые горячие. Глубина 3 дня → опрос каждого слова раз в 2 дня, ничего не теряется.
3. **TGStat** — позже, при бюджете.

К��ждое слово имеет рейтинг: сколько лидов из него дошло до ответа. Слабые слова бот предлагает заменить.

### 4.3 Ручной ввод
Любой сотрудник пересылает боту пост или отправляет ссылку `t.me/…` / сайт → кандидат идёт в общий пайплайн, получает ИИ-анализ и скоринг. Автор ручного лида получает приоритет на его захват в течение 10 минут.

### 4.4 База Telegram Ads (Trustat, платный тариф — этап 4)
Поиск объявлений Telegram Ads по ключевым словам/доменам → рекламодатели с подтверждённым бюджетом.

### 4.5 Что не источник
Парсинг участников чатов, массовый сбор личных данных, покупные базы — нет. Работаем только с публичными каналами и их публичными контактами.

## 5. Пайплайн обработки лида

```
Кандидат → Нормализация → Дедуп и стоп-листы → Обогащение → ИИ-анализ → Скоринг → Очередь
```

### 5.1 Нормализация
Единый ключ сущности: `username` в нижнем регистре без `@`, либо домен без `www`, либо бренд (нормализованный) — в порядке приоритета. Одна сущность — один лид, сколько бы раз она ни встретилась.

### 5.2 Дедуп и стоп-листы
- Уже есть лид с этой сущностью в активном статусе → не создавать, а **обогатить** существующий («ещё одно размещение — в канале X»). Ответственный SDR получает уведомление: появился новый факт для касания.
- Лид в статусе LOST/NOT_TARGET/POSTPONED → **cooldown 60 дней** (настраивается). После cooldown можно повторно, с пометкой «повторный».
- **Чёрный список** (владелец): конкуренты-агентства, скам, спорные тематики. Автоотсев с логом.
- **Список клиентов** (старший): текущие и прошлые клиенты → не в очередь, а уведомление аккаунт-менеджеру «клиент X закупился у конкурента» — повод для касания.
- **Красный список контактов** — см. 5.2a. Действует на уровне человека, а не канала.
- **Связывание сущностей.** Один бизнес — это часто канал + сайт + бот-магазин + менеджер. Если описание канала ссылается на сайт, а сайт — на канал, бот склеивает их в один лид автоматически. Если не увидел — на карточке есть `[ Объединить с #… ]`. Иначе два SDR напишут одному клиенту с разных лидов, и со стороны это выглядит как спам.

### 5.2a Красный список контактов — кому нельзя писать про рекламу
Зачем: после 2–3 жалоб «спам» Telegram ограничивает аккаунт SDR (писать можно только контактам) на дни — сотрудник выпадает из работы. Плюс репутация: позиционирование MORIER не переживёт «вы же просили не писать, а мы снова».

**Уровни.**
| Уровень | Кто | Что видит SDR |
|---|---|---|
| **Красный** — никогда | просил не писать, жаловался, угрожал, решение владельца | контакт скрыт, красный баннер с причиной; кнопка «Написал» для этого контакта отключена |
| **Оранжевый** — только старший/владелец | админы каналов базы MORIER (это поставщики, не клиенты), крупные текущие клиенты, партнёры | «Контакт закрыт для SDR» + кнопка `[ Передать старшему ]` сразу |
| **Жёлтый** — временно | «не сейчас, напишите через N месяцев», «бюджет в следующем квартале» | контакт скрыт до даты; по истечении лид возвращается в очередь с пометкой «просил вернуться в октябре» — это тёплый повод |

**Как попадают в список.**
- Кнопка `[ Просил не писать ]` на карточке лида у SDR → контакт в красный, лид → NOT_TARGET с причиной «отказ от контакта», cooldown сущности 180 дней вместо 60. SDR за честную метку получает +2, не минус — иначе будут скрывать.
- `/dnc @user причина [срок]` — старший и владелец. Можно **переслать боту любое сообщение от человека** с командой `/dnc` — для юзеров без username.
- Автоматически в оранжевый: все контакты админов из таблицы каналов MORIER (8.1) и менеджеры из списка клиентов.
- Импорт CSV на этапе 0: у команды такой список наверняка уже есть в голове.
- Снятие с красного — только владелец, с причиной в журнале.

**Как работает технически.**
- Сопоставление по **user_id**, не по username: username меняют. При добавлении сканер один раз резолвит @username → id и хранит оба; при извлечении контакта из лида — то же самое. Смена ника не спасает от флага.
- Флаг ставится на человека и **распространяется на все лиды**, где он контакт, — сразу, включая активные: владельцу активного лида уходит личное уведомление «контакт @x закрыт: причина».
- Если у лида остался только красный контакт и нет другого — лид в очередь не идёт, статус «Без контакта», виден старшему.
- `/find @user` и `/check @user` (любая роль) — мгновенный ответ до того, как человек открыл диалог: чист / красный / оранжевый / жёлтый до даты, причина, кто внёс.
- Проверка сообщения `[ Проверить сообщение ]` (6.5): если в черновике упомянут @username из красного списка — предупреждение.
- Честно про границу: бот не видит, кому SDR реально отправил сообщение. Закрывается видимостью (контакт скрыт), экономикой (−15 за подтверждённое письмо в красный список) и тем, что такой контакт после жалобы всё равно всплывёт у старшего.
- Список — про людей. Если человек попросил не писать «всей компании», владелец дополнительно вносит сущность в чёрный список (5.2). Если канал сменил менеджера — новый контакт чист, и это правильно.

### 5.3 Обогащение
Из MTProto: подписчики, описание, последний пост, 10 последних постов (текст), средние просмотры, есть ли «по рекламе» контакт, ссылки. Из истории самого бота: где и когда этот рекламодатель уже размещался. Из Trustat (если лимит позволяет и score предварительно ≥ 60): `quality_score`, ER, динамика.

### 5.4 ИИ-анализ
Одна модель, один запрос, строгий JSON-ответ. Вход: описание + 10 постов + найденные размещения + список вертикалей MORIER + 10–20 few-shot примеров из размеченной базы (похожие по эмбеддингу). Выход:

```json
{
  "is_business": true,
  "niche": "продажа ключей и гифтов Steam",
  "sells": "ключи, гифты, пополнение кошелька",
  "audience": "ПК-геймеры 16-30, охотники за скидками",
  "budget_signals": ["размещался в FORGE CS2 2 дня назад", "3 рекламы за 30 дней", "есть сайт и бот-магазин"],
  "activity": "активен, последний пост 6 ч назад",
  "morier_verticals": ["Steam", "CS2", "Dota 2"],
  "contact": {"username": "keydrop_manager", "source": "описание канала: 'по рекламе'"},
  "personal_fact": "заметил ваше размещение у FORGE CS2 на этой неделе",
  "first_message_draft": "…по скрипту SDR…",
  "red_flags": [],
  "is_competitor_agency": false,
  "ai_score": 82,
  "reasons": ["уже покупает рекламу в нашей нише", "есть контакт", "активен"]
}
```

**Модель.** Критерии: цена, качество русского, JSON-режим. По прайсу Vercel AI Gateway на сентябрь 2026 — кандидаты:
- `deepseek/deepseek-v4-flash` — $0.08 / $0.18 за 1M токенов (вход/выход) — основной.
- `openai/gpt-4.1-nano` — $0.10 / $0.40 — запасной.
Перед стартом перепроверить актуальные ID и цены; в коде модель — параметр конфигурации, меняется без деплоя.

**Стоимость.** Анализ лида ≈ 3 000 токенов на вход + 600 на выход ≈ **$0.0004 (≈ 0,04 ₽)**. Классификация спорного рекламного поста ≈ 800 токенов ≈ $0.0001. При 1 000 лидов и 10 000 постов в месяц — **менее $2**. Эмбеддинги для похожести — порядка $0.02 за 1M токенов, копейки. Полный расход ИИ виден владельцу в дашборде.

### 5.5 Скоринг (0–100)
**v1 — правила** (веса настраиваются владельцем в боте):

| Сигнал | Баллы |
|---|---|
| Найден в рекламном посте (уже покупает рекламу) | +30 |
| 3+ размещений за 30 дней | +10 |
| Ниша совпадает с вертикалями MORIER | +20 |
| Есть прямой контакт «по рекламе» | +15 |
| Есть продукт: сайт / бот-магазин / прайс | +15 |
| Активность за 14 дней | +10 |
| Подписчики 1k–100k (проект «уже что-то делает», но не корпорация) | +10 |
| Мёртвый канал (нет постов 30 дней) | −40 |
| Конкурент-агентство | −60 |
| Стоп-тематика (по списку владельца) | −100 |

Финальный score = 0,6 × правила + 0,4 × ai_score (пока нет модели v2). Категории: **Горячий** ≥ 70, **Тёплый** 40–69, **Холодный** < 40 (в очередь не попадает, лежит в «архиве кандидатов», доступен по поиску).

**v2 — обучаемая модель** (раздел 10) заменяет веса правил на выученные.

## 6. Очередь и захват лида

### 6.1 Где живёт очередь
Приватная группа команды «MORIER · Лиды». Бот публикует карточку с кнопками. Параллельно у каждого SDR есть личный раздел «Очередь» в боте с фильтрами по вертикали и категории.

**Правило тишины.** В группу попадают только новые карточки лидов и лидерборд по понедельникам. Напоминания, таймеры, дайджесты, подсказки — только в личку. Иначе группу замьютят через неделю, и очередь перестанут смотреть.

### 6.2 Карточка в очереди
```
ЛИД #1042 · Горячий · 82
KeyDrop RU — магазин ключей Steam
@keydrop_ru · 14 200 подп. · активен (пост 6 ч назад)

Почему лид: размещался в «FORGE CS2» 2 дня назад (erid),
3 размещения за 30 дней в гейминг-каналах.
Ниша: ключи и гифты Steam → наши вертикали: Steam, CS2, Dota 2
Контакт: @keydrop_manager («по рекламе» в описании)
Факт для первого сообщения: «заметил ваше размещение у FORGE CS2 на этой неделе»
Риски: нет

[ Беру ]   [ Нецелевой ]   [ Дубликат ]
```

Та же карточка, если контакт в красном списке:
```
Контакт: 🚫 закрыт (красный список · «просил не писать», 12.08, внёс @senior)
Другой контакт: не найден → лид виден только старшему
```

### 6.3 Правило первого клика
Захват — атомарная операция в БД (`UPDATE … WHERE id=? AND status='NEW'`). Успех только у одного. Карточка в группе редактируется: «Взял @ivan · 14:02». Остальным — короткий тост «Уже взял @ivan».

### 6.4 Ограничения захвата (защита от «хапанья»)
- Не более **5 активных лидов** одновременно на SDR (активный = взят, но клиент ещё не ответил). Настраивается.
- После захвата у SDR **30 минут** (в рабочее время 10:00–20:00; ночью таймер стартует в 10:00) на подтверждение первого контакта.
- Подтверждение = SDR **пересылает боту своё отправленное клиенту сообщение**. Бот фиксирует время, проверяет ИИ-чеком наличие персонализированного факта и соответствие скрипту (только подсказка, не блокировка).
- Не подтвердил за 30 минут → лид **автоматически возвращается в очередь** с пометкой «освободился», этому SDR повторный захват этого лида закрыт. Это и есть «штраф» — естественный, без денег.
- За 15 и 5 минут до конца — напоминание в личку.

### 6.5 Личная карточка лида у SDR (после захвата)
Всё из карточки очереди + черновик первого сообщения по скрипту SDR (редактируется человеком!) + кнопки:
`[ Написал — переслать сообщение ]` `[ Клиент ответил ]` `[ Нецелевой ]` `[ Просил не писать ]` `[ Отложить ]` `[ Передать старшему ]` `[ Заметка ]`

Плюс `[ Проверить сообщение ]`: SDR присылает черновик **до отправки клиенту**, бот за 3 секунды отвечает по чек-листу инструкции — есть ли персональный факт, нет ли точной цены вместо вилки, нет ли «здравствуйте, мы агентство…» в первой строке, длина ≤ 5 строк, есть ли вопрос в конце. Для новичка это главная функция: ошибку ловим до клиента, а не после.

### 6.6 Старение очереди
- Горячий лид не взят **15 минут** в рабочее время → личный пинг всем SDR, у кого не исчерпан лимит активных.
- Лид висит **24 часа** → карточка перепубликуется с пометкой «никто не взял» и уходит старшему: либо берёт сам, либо метит нецелевым — и это метка для обучения (скоринг ошибся).
- **5 дней** без захвата → архив кандидатов. Из архива лид вернётся сам, если сканер увидит новое размещение.

## 7. Жизненный цикл лида и каденция касаний

### 7.1 Статусы
`NEW → CLAIMED → CONTACTED → REPLIED → QUALIFIED → HANDED_OFF → ACCEPTED → WON | LOST`
Боковые: `RELEASED` (вернулся в очередь по таймеру), `NOT_TARGET`, `DUPLICATE`, `POSTPONED` (после 4-го касания), `BLACKLISTED`.

Каждый переход пишется в журнал событий (кто, когда, откуда, комментарий). Журнал — основа и рейтинга, и обучения.

### 7.2 Каденция касаний — бот напоминает и подсказывает
Прямо из SDR-инструкции:

| Касание | Когда | Бот делает |
|---|---|---|
| 1 | День 0 | Черновик по скрипту с персональным фактом |
| 2 | +3 дня | Напоминание + подсказка: «пришли скрин статы канала из вертикали клиента» — бот сам прикладывает актуальный пост из канала MORIER ЦЕНЫ по вертикали |
| 3 | +7 дней | Напоминание + подсказка: соцдоказательство/кейс из ниши (бот показывает WON-лидов из той же ниши, если есть) |
| 4 | +7 дней | Напоминание + шаблон последнего касания → статус POSTPONED |

Касание подтверждается пересылкой сообщения. Просроченное касание — не штраф, а падающий приоритет: лид с просрочкой > 48 ч подсвечивается старшему как «зависший», после 5 дней — возвращается в очередь.

### 7.3 Новый факт по активному лиду
Если монитор рекламы увидел новое размещение рекламодателя, у которого уже есть ответственный SDR, — SDR получает уведомление: «Твой лид @keydrop_ru вчера разместился в «Игры Стим». Повод для касания». Это самая сильная функция для доведения до ответа.

### 7.4 Отпуск и уход сотрудника
Владелец ставит сотруднику паузу → его лиды в CLAIMED/CONTACTED возвращаются в очередь с пометкой «от @ivan, история внутри»; лиды в REPLIED и дальше назначаются на указанного коллегу со всей историей касаний и пересланных сообщений. Клиент не должен почувствовать смену человека.

## 8. Передача старшему

1. SDR жмёт `[ Передать старшему ]`. Бот **сам собирает карточку в формате инструкции**:
   ```
   Ник: @keydrop_manager
   Проект: t.me/keydrop_ru
   Суть проекта: магазин ключей Steam, 14k подписчиков, активен
   Статус: спросил цену — дал вилку 3–8k
   Важные детали: бюджет ~30k/мес, размещался у FORGE CS2, интересуют CS2 и Steam
   Касание: ответил на 2-м
   ```
   Поля «Статус», «Детали», «Касание» SDR заполняет в 3 шага кнопками/текстом; остальное — из данных.
   Бот автоматически прикладывает: ссылку на креатив клиента (если найден в размещении), 3 последних размещения клиента с реальным охватом и **матрицу размещаемости** — каналы MORIER в вертикалях клиента с флагом, принимают ли они тематику (8.1).
2. SDR пересылает боту ключевые сообщения клиента (пересылкой, не скрином — как требует инструкция). Бот прикладывает к карточке.
3. Проверка полноты: без статуса и деталей передать нельзя.
4. Старший получает карточку с кнопками `[ Принял ]` `[ Вернуть на доработку: что не хватает ]`. SLA принятия — **2 часа в рабочее время**; при просрочке — уведомление владельцу.
5. Исход ставит старший: `[ WON: сумма, маржа ]` или `[ LOST: причина из списка ]` (дорого / не ответил / ушёл к конкуренту / не сезон / другое). Причина LOST — обязательна: это метка для обучения.

### 8.1 Таблица каналов MORIER — бот знает продукт
Отдельная таблица `morier_channels`: канал, вертикаль, подписчики, охват/24ч, цена продажи, закупочная цена (видит только владелец), категория A/B/C, **флаги тематик** (беттинг / казино / крипта / 18+ / VPN — принимает или нет), контакт админа, дата последнего обновления статы. Ведёт старший или байер; раз в неделю бот напоминает обновить цифры. Из этой таблицы:
- `/catalog <вертикаль>` — SDR за секунду видит каналы вертикали в формате строки канала ЦЕНЫ. Не нужно листать каталог.
- `/price <вертикаль>` — **разрешённая вилка** для SDR по инструкции. Бот отдаёт диапазон, а не прайс, — SDR физически не может назвать точную цену.
- Матрица размещаемости при передаче старшему (2.4).
- Автоподбор поста для касания 2 (7.2).
- Каналы категории C не показываются никому, кроме владельца.

## 9. Рейтинг вместо штрафов

### 9.1 Принципы
- Рейтинг — **очки, не деньги**. Деньги считаются по марже закрытых сделок, вне бота, по существующей политике оплаты. Прямой конвертации очков в рубли нет — иначе начнут фармить.
- Очки даются за **результат и дисциплину**, а не за активность ради активности. За захват лида — 0.
- Отрицательные события есть, но они мягкие и заменяют штрафы естественными последствиями (потеря лида, снижение лимита).
- **Сезоны по месяцам**: рейтинг обнуляется 1-го числа, «зал славы» хранит суммарные очки за всё время. Новичок каждый месяц стартует на равных.

### 9.2 Таблица событий

| Событие | Очки |
|---|---|
| Первый контакт подтверждён ≤ 30 мин после захвата | +10 |
| Первый контакт подтверждён ≤ 2 ч | +5 |
| В первом сообщении есть персонализированный факт (ИИ-чек) | +3 |
| Касание 2 / 3 / 4 сделано в срок (±1 день) | +2 каждое |
| Клиент ответил | +15 |
| Лид передан старшему и **принят** без возврата | +25 |
| Сделка WON (ставит старший) | +50 |
| Повторная сделка с тем же клиентом | +30 |
| Верно помечен «нецелевой» / «дубликат» (подтверждено старшим или владельцем выборочно) | +1 |
| Честно отметил «просил не писать» (контакт в красный список) | +2 |
| Лид освобождён по таймеру (не написал за 30 мин) | −5 |
| Написал контакту из красного списка (подтверждено старшим) | −15 |
| Карточка возвращена старшим на доработку | −3 |
| 3 освобождения по таймеру за неделю | лимит активных лидов → 1 на 3 дня |

### 9.3 Уровни и видимость
Уровни: Новичок (0–99) → Охотник (100–299) → Снайпер (300–699) → Закрыватель (700+). Уровень виден в лидерборде и рядом с именем в группе.
Лидерборд: команда `/top` и автопост в группу каждый понедельник 10:00 (неделя) и 1-го числа (месяц). Показывается: очки, лидов взято, ответов, передано, WON, медиана времени первого контакта.
Личная статистика `/me`: то же по себе + сравнение с медианой команды + «что подтянуть».

### 9.4 Ручная корректировка владельцем
`/adjust @user +20 причина` — то, что раньше называлось «прибавить/убавить баланс». Обязателен комментарий, запись в журнал, сотрудник получает уведомление с причиной. Лимит: ±50 за раз.

### 9.5 Утренний план и вечерний разбор
**10:00** каждому SDR — план дня одним сообщением: касания по расписанию (кнопки «сделал / перенести»), лиды без ответа > 3 дней, сколько взять из очереди до плана 20–30 касаний, горячие лиды в очереди по его вертикалям.
**20:30** — разбор: касаний сделано / план, ответов, зависших лидов, очки за день. Владельцу — сводка по команде.

### 9.6 Новичок: допуск и наставник
- **Квиз перед допуском к очереди**: 10 вопросов по SDR-инструкции и гайду по возражениям (вилка цены, что нельзя писать первым сообщением, когда передавать старшему, как подтверждать касание). Порог 8/10, пересдача через час. Вопросы — в базе знаний, владелец правит.
- **Первые 5 лидов новичка**: копии его первых сообщений уходят старшему после отправки (не до — что��ы не ломать 30-минутный SLA). Старший одной кнопкой: «ок» / «замечание: …». Замечание — новичку в личку.
- Уровень «Новичок» снимается автоматически после 5 принятых старшим лидов.

## 10. Самообучение на собранных данных

### 10.1 Что собираем (с первого дня, автоматически)
Для каждого лида: все входные данные (описание, посты, сигналы, источник, ключевое слово, донорский канал), полный ответ ИИ, score v1, кто взял, время до контакта, текст первого сообщения, ответил ли, за сколько, причина LOST/NOT_TARGET, WON с суммой и маржой. Это размеченный датасет, растущий сам.

Плюс одна ручная метка в один тап: под каждым ИИ-черновиком и подсказкой суфлёра — `[ Полезно ] [ Мимо ]`. Самый дешёвый способ научить бота писать «как у нас»: через месяц владелец видит, какие формулировки команда переписывает, и правит промпт.

### 10.2 Уровень 1 — few-shot из своей базы (работает с ~30 размеченных лидов)
При анализе нового лида бот ищет по эмбеддингу описания 10 самых похожих размеченных лидов (5 успешных, 5 нецелевых/провальных) и подставляет их в промпт как примеры: «вот кого мы считаем целевым, вот кого нет». Модель начинает оценивать «глазами MORIER». Стоимость — +1 500 токенов на запрос, ≈ 0,01 ₽.

### 10.3 Уровень 2 — собственная модель скоринга (с ~150 размеченных лидов)
Ночная задача на сервере: логистическая регрессия или градиентный бустинг (scikit-learn) на признаках (подписчики, активность, число размещений, вертикаль, наличие контакта, источник, ai_score, эмбеддинг описания) → две цели: `P(ответит)` и `P(купит)`. Новый score = калиброванная вероятность. Модель версионируется; если новая версия хуже старой на отложенной выборке — не применяется, владелец получает отчёт. Требования к железу — секунды на 1 vCPU.

### 10.4 Уровень 3 — fine-tune (не раньше 500+ лидов, опционально)
Только если уровни 1–2 упёрлись в потолок. Решение принимает владелец по отчёту.

### 10.5 Что ещё учится
- **Донорские каналы**: сколько лидов из канала дошло до ответа/сделки → приоритет мониторинга, слабые каналы — предложение отписаться.
- **Ключевые слова**: конверсия слова → ротация, бот предлагает новые слова из ниш WON-клиентов.
- **Шаблоны первого сообщения**: 2–3 варианта формулировок скрипта (в рамках инструкции) → доля ответов по каждому → бот подставляет лучший, статистика владельцу.
- **Причины LOST**: агрегируются по нишам → владелец видит, где «дорого», где «не сезон», — вход для ценовой политики.

### 10.5a Побочные продукты данных (бесплатно, из того же потока)
- **Кандидаты в базу.** Сканер видит каналы, где рекламодатели вашей ниши размещаются часто, а в базе MORIER их нет → раз в неделю владельцу список с реальным охватом рекламы и частотой размещений. Работа закупщика, сделанная данными.
- **Календарь инфоповодов гейминга.** Таблица событий (распродажи Steam, крупные обновления Brawl Stars / CS2 / Dota 2, релизы, турниры): заполняет владелец или контент-менеджер, часть ИИ подтягивает из новостных каналов базы. За 7–10 дней до события бот поднимает скоринг лидов смежных ниш и подставляет повод в касание: «через неделю распродажа Steam — магазины ключей как раз планируют закупку».

### 10.6 Суфлёр по возражениям (дешёвая и очень полезная функция)
SDR пересылает боту ответ клиента → бот по «Гайду по возражениям» и инструкциям (загружены как база знаний) предлагает 1–2 варианта ответа и следующий шаг. Отвечает человек. Стоимость запроса — около 0,05 ₽.

## 13. Архитектура и стек

### 13.1 Стек
- **Python 3.12** — потому что и бот, и MTProto, и ML живут в одной экосистеме.
- **aiogram 3** — Telegram Bot API (интерфейс сотрудников).
- **Telethon** — MTProto-клиент аккаунта-сканера (чтение каналов).
- **SQLite (WAL)** — старт; миграция на **PostgreSQL** при > 100 000 событий или 3+ параллельных процессах. Схема через Alembic с первого дня, чтобы миграция была безболезненной.
- **APScheduler** — таймеры SLA, каденция, ночное обучение, дайджесты, бэкапы.
- **scikit-learn + numpy** — скоринг v2.
- **httpx** — Trustat REST, ИИ-API, лёгкие HTTP-проверки сайтов.
- ИИ — через **Vercel AI Gateway** (один ключ, любые модели, единый счёт) или напрямую API DeepSeek; выбор — параметр конфигурации.
- **NSSM** — запуск как служба Windows с автоперезапуском. Два процесса-службы: `bot` и `scanner`, общая БД.
- Логи — файлы с ротацией + критические ошибки в личку владельцу.

### 13.2 Бюджет ресурсов
Бот ≈ 80–120 MB RAM, сканер ≈ 100–150 MB, SQLite — мало, ночное обучение — пик до 300 MB на минуты. Итого < 1 GB из 2 — запас есть. CPU в простое ≈ 0.

### 13.3 Надёжность
- Ежедневный дамп БД + конфиги → архив → отправка в приватный канал «MORIER · Backup» через бота (бесплатно, вне сервера). Хранить 30 дней.
- Идемпотентность обработчиков: повторное нажатие кнопки не создаёт дублей.
- Health-check: если сканер не получал обновлений 2 часа в рабочее время — уведомление владельцу.
- Все секреты — в `.env`, права только у Administrator, в репозиторий не попадают.

### 13.4 Модель данных (основные таблицы)
`users` (tg_id, роль, статус, лимиты) · `leads` (сущность, ключ, статус, score, категория, owner_id, време��а) · `lead_signals` (размещения, сигналы бюджета) · `lead_ai_runs` (вход, выход, модель, токены, цена) · `lead_events` (журнал переходов, автор, комментарий) · `touches` (номер касания, план, факт, доказательство) · `handoffs` (карточка, старший, принято/возвращено, исход, сумма, маржа) · `rating_ledger` (сотрудник, событие, очки, причина, сезон) · `sources` (тип, конфиг, рейтинг полезности) · `donor_channels` · `keywords` · `blacklist` · `clients` · `ad_posts` (пост-донор, рекламодатель, детектор, уверенность, просмотры 24/48 ч, продавец-агентство) · `morier_channels` (каталог, цены, флаги тематик, A/B/C) · `dnc_contacts` (user_id, username на момент внесения, уровень, причина, кто внёс, срок, история) · `api_keys` (поставщик, ключ шифрованно, владелец ключа, лимиты, расход, сброс, статус, слова) · `events_calendar` · `knowledge_base` (инструкции, гайд, квиз) · `models` (версия, метрики, активна) · `settings`.

## 14. Безопасност�� и соответствие

- Сменить пароль сервера (утёк скриншотом). RDP — по белому списку IP, аккаунт `Administrator` переименовать, включить Windows Defender Firewall.
- Аккаунт-сканер: отдельный номер, 2FA, сессия хранится зашифрованно, никаких исходящих сообщений.
- Бот принимает команды только от белого списка user_id; всё остальное — молчание.
- Храним только публичные данные каналов и рабочую переписку сотрудников с клиентами, которую сотрудник сам пересылает. Никаких персональных данных пользователей каналов.
- Журнал действий не удаляется; корректировки рейтинга — только с причиной.
- API-ключи (свои и друзей) хранятся шифрованно, в интерфейсе показываются только последние 4 символа. Ключ друга можно отозвать одной командой — по его просьбе, без вопросов.
- Красный список — единственное место, где хранится идентификатор человека вне лидов. Хранится только id, ник на момент внесения и причина; ничего лишнего.

## 17. Риски и как закрыты

| Риск | Ответ |
|---|---|
| Бан аккаунта-сканера | Отдельный номер, прогрев, лимиты, только чтение, авто-стоп при FloodWait; запасной аккаунт заранее |
| Много «мусорных» лидов в начале | Порог Горячий/Тёплый, холодные не в очередь, few-shot с первых 30 меток, кнопка «нецелевой» с причиной |
| SDR хватают лиды ради очков | За захват 0 очков, лимит активных, авто-освобождение, снижение лимита за повторы |
| Trustat поменяет лимиты/цены | Trustat — вспомогательный; ядро на MTProto |
| Trustat забанит пул бесплатных ключей с одного IP | Ожидаемо. Бот продолжает работать без Trustat (карточка с пометкой «данные MTProto»); решение — Medium за 249 ₽. Друзья предупреждены о риске заранее |
| SDR написал человеку из красного списка | Контакт скрыт на карточке, `/check` до диалога, −15 при подтверждении, уровень «Новичок» — обязательная проверка первых сообщений старшим |
| Человек сменил username и снова попал в лиды | Сопоставление по user_id, а не по нику |
| Смена цен/ID моделей ИИ | Модель — параметр конфигурации; расход виден в дашборде |
| Падение сервера | Службы с автоперезапуском, ежедневный бэкап в Telegram, восстановление на любой VPS за час |
| Утечка данных | Белый список, секреты в `.env`, нет персональных данных подписчиков |
| SDR «подтверждает контакт» пересылкой сообщения, которое клиенту не отправлял | Технически бот не видит получателя. Закрыто экономикой: за контакт всего +10; за ответ клиента +15 — и он требует пересылки сообщения *от клиента*; WON ставит старший. Плюс выборочная проверка старшим 1 из 10 и −20 за подтверждённую подделку |
| Реклама казино — юридический риск для агентства и каналов | Жёлтый список, флаг «лицензия / нет» от ИИ, матрица размещаемости, решение только за старшим; бот сам ничего не размещает |
| Таблица каналов устарела — SDR даёт неверную вилку | Еженедельное напоминание ответственному; если стата старше 14 дней, `/price` показывает пометку «данные устарели» |

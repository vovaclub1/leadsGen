# LeadHunter — бот MORIER для поиска и ведения рекламодателей

Telegram-бот на aiogram 3 + SQLite. Ищет рекламодателей в каналах-донорах и по ключевым словам (Trustat API),
раздаёт лиды команде в группу, держит SLA первого контакта, ведёт каденцию касаний, рейтинг и красный список.
Чужие в бота не попадают: доступ только у людей, которых владелец добавил по Telegram ID.

## Быстрый запуск (VPS с Docker)

```bash
git clone <репозиторий> && cd bot
cp .env.example .env          # заполните BOT_TOKEN и OWNER_ID — остальное можно позже
docker compose up -d --build
docker compose logs -f        # должно быть: «Бот @... запущен. Владелец: <ваш ID>»
```

Без Docker: `python3.11 -m venv .venv && .venv/bin/pip install -r requirements.txt && .venv/bin/python main.py`.

## Первые 10 минут после запуска

1. Напишите боту `/start` с аккаунта `OWNER_ID` — вы владелец.
2. Добавьте бота в группу лидов админом и отправьте там `/bind`.
3. `/admin → Сотрудники → Добавить` → пришлите Telegram ID сотрудника → выберите роль (SDR / Старший / Байер).
   Сотрудник узнаёт свой ID, написав боту `/start`: в отказе бот показывает его ID.
4. `/admin → API-ключи → Добавить ключ` → вставьте ключ Trustat. Бот сам проверит его через `/usage/info`
   и покажет тариф, период, расход по трём осям и то, что ключу разрешено. Пакет (**Stat** или **Search**)
   он определяет сам по `scopes` ключа — вручную выбирать не нужно. Подробности — в разделе «Ключи Trustat».
5. `/admin → Каналы-доноры → Добавить` → список каналов, где размещаются ваши потенциальные клиенты.
   Сканер заработает после заполнения `TG_API_ID`/`TG_API_HASH` и одноразового `python login_scanner.py`
   с **отдельного** аккаунта (не личного).
6. `/admin → Красный список → Добавить` → @username или ID человека → уровень → причина.
   🚫 красный — никогда не писать, 🟠 оранжевый — только старший, 🟡 жёлтый — временно.
7. `/admin → 🤖 ИИ → Проверить ИИ` → бот сходит в DeepSeek текстом и картинкой и скажет, всё ли в порядке.

## Ключи Trustat — пакеты, лимиты и резерв

Бот работает с Public API Trustat (`https://api-public.trustat.me`, префикс `/public/v1`, ключ в заголовке
`X-API-Key`). Ключей можно добавить сколько угодно: бот сам маршрутизирует запросы и переживает исчерпание
квоты без вашего участия.

### Пакеты определяются по `scopes`, а не вручную

При добавлении бот дёргает `/usage/info` (этот запрос не тарифицируется) и смотрит, что ключу разрешено:

| `scopes` у ключа | Пакет в боте | Что на нём работает |
|---|---|---|
| `channels`, `stats` | **Stat** | карточки каналов, статистика, `/lookup`, батч-загрузка |
| `posts` | **Search** | поиск по ключевым словам (`/posts/search`) |

Один ключ может иметь оба пакета сразу — тогда он участвует в обеих ротациях. Если ключ не даёт ни одного
из нужных scope, бот скажет об этом сразу, а не при первом рабочем запросе.

### Три оси тарификации

Trustat считает расход не только по числу запросов, поэтому бот показывает все три:

| Ось | Что списывает |
|---|---|
| запросы | любой вызов API |
| уникальные каналы | обращение к карточке или статистике канала |
| результаты списков | выдача поиска и батчей |

Отсюда правило экономии, заложенное в бот: `/posts/search` стоит 1 запрос и **не** тратит уникальные каналы,
а `/channels/batch` забирает до 100 каналов за один запрос вместо ста поштучных карточек. Обычный `@username`
уходит в API как есть; через `/lookup` прогоняются только ссылки со слэшами (`t.me/name/123`) и приватные
`+hash` — платить за резолв там, где он не нужен, бот не станет.

Остаток бот берёт из заголовков `X-Quota-*` ответа и перезаписывает им свои локальные счётчики: API считает
точнее. Строка расхода приходит в виде `«120/500»`; безлимит выглядит как `«120/0»` или `«120/-»` и лимитом
не считается.

### Резерв 20 %

Когда по пакету остаётся **20 % месячной квоты или меньше, обычные запросы перестают проходить** — в логе
появится «Пул ключей (stat) в резерве». Остаток придерживается под приоритетные вызовы: то, что происходит
по прямому действию человека (SDR открыл карточку лида, вы проверяете канал руками). Фоновые задачи —
обогащение и автопоиск — в это время просто молчат.

Это не поломка и не требует вмешательства. Чтобы снять резерв, добавьте ещё один ключ: порог считается по
сумме лимитов всех активных ключей пакета, и новый ключ сразу поднимает пул выше границы.

Владелец узнаёт о резерве не только из лога: раз в сутки бот сам пишет в личку, если остаток пакета
ниже 20% или, при текущем темпе расхода, закончится в ближайшие 3 дня (ТЗ 2.1a) — не нужно самому
ходить в `/keys` и считать вручную.

### Как бот реагирует на ответы API

| Код | Что делает бот |
|---|---|
| 426 | помечает ключ `exhausted` и прозрачно повторяет запрос на следующем ключе |
| 401 / 403 | помечает ключ `banned` (ключ отозван или без нужного scope) — нужен новый |
| 429 | ждёт столько, сколько просит `Retry-After` (не больше 10 с), и повторяет на том же ключе |
| 503 | пауза 2 секунды и повтор; ключ не наказывается |
| 404 | считает запрос потраченным и отдаёт «не найдено» |

Первого числа месяца счётчики обнуляются, а ключи со статусом `exhausted` автоматически возвращаются в строй.
Дневные лимиты сбрасываются каждую ночь. Бесплатный тариф по умолчанию: Stat — 10 запросов в день ������ 50 в месяц,
Search — 100 в месяц без дневного потолка.

### Поиск по ключевым словам

`/admin → Ключевые слова` — фразы вроде «ищу каналы для рекламы». Бот опрашивает `/posts/search` с
`peer_type=all`, потому что спрос на рекламу чаще пишут в чатах-барахолках, чем в каналах, и скрывает репосты.

Важно: в ответе API **нет готовой ссылки на пост** — только `channel_id` и `message_id`. Лидом становится
**автор поста**, а его данные бот добирает батчем через `/channels/batch`. Если батч не ответил, ссылка
вытягивается из текста самого поста. Один ��втор в пределах прогона засчитывается один раз.

Каждое слово опрашивается раз в 2 дня, глубина поиска — 3 дня (ТЗ 4.2: «ничего не теряется»), а не
чаще: на бесплатном тарифе 100 запросов/мес на ключ, и более частый опрос сжигает квоту слова
за первую неделю месяца.

## Сканер каналов — пошаговая настройка

Сканер — это ��лавный источник лидов: он ��итает посты в каналах-донорах и вылавливает тех, кто там
рекламируется. Работает не через бота, а через обычный Telegram-аккаунт (протокол MTProto), потому что
боты не умеют читать чужие каналы, в которых их не сделали админом.

Если в посте спроса нет ни ссылки, ни @упоминания, лид всё равно создаётся: карточка с пометкой
«Контакт в посте не найден» уезжает в группу, SDR открывает пост по ссылке и ищет связь вручную.
Каждый такой пост — отдельный лид (ключ по посту, а не по донору).

**Реальный охват (ТЗ 4.1).** Просмотры рекламного поста в момент публикации почти всегда занижены —
сканер перечитывает их через 24 и 48 часов (`ad_posts.views_24h`/`views_48h`) фоновой задачей раз
в ~30 минут. При передаче старшему бот прикладывает 3 последних размещения клиента с этим реальным
охватом — аргумент в продаже и проверка собственной «гарантии охвата».

### Шаг 1. Заведите отдельный аккаунт

**Не используйте личный номер.** Аккаунт будет вступать в десятки каналов и постоянно читать их —
Telegram может ограничить его за подозрительную активность. Потеря рабочего аккаунта ничего не ломает:
бот, лиды и база живут отдельно, вы просто повторяете шаги 2–4 с новым номером.

- Нужна SIM-карта. Подойдёт дешёвая физическая симка любого оператора.
- Виртуальные номера из интернета брать не стоит: их массово банят, а номер могут перекупить вместе
  с доступом к вашему аккаунту.
- Зарегистрируйте на этот номер Telegram обычным способом (телефон или Telegram Desktop).
- Поставьте аккаунту имя и аватар, вступите в 3–5 любых популярных каналов и оставьте его на день.
  Свежий пустой аккаунт, который сразу вступает в 30 каналов, улетает в ограничения гораздо чаще.

### Шаг 2. Получите `api_id` и `api_hash` на my.telegram.org

Это бесплатно и делается один раз.

1. Откройте [my.telegram.org](https://my.telegram.org) **в браузере**.
2. Введите номер нового аккаунта в международном формате: `+79991234567`.
3. Нажмите **Next**. Код придёт **не по SMS, а сообщением в сам Telegram** от аккаунта «Telegram».
   Откройте приложение, скопируйте код, вставьте на сайте.
4. Выберите пункт **API development tools**.
5. Заполните форму:
   - **App title**: `LeadHunter`
   - **Short name**: `leadhunter`
   - **Platform**: Desktop
   - **URL** и **Description** можно оставить пустыми.
6. Нажмите **Create application**. Откроется страница с двумя значениями:
   - **App api_id** — число, например `2040123`
   - **App api_hash** — строка из 32 символов

Эти два значения — пароль от аккаунта в обход пароля. Никому их не показывайте, в скриншотах закрывайте.

> Если сайт отвечает `ERROR`, подождите 10–15 минут и попробуйте снова — у my.telegram.org так бывает
> на свежих аккаунтах. Иногда помогает другой браузер или отключение VPN.

### Шаг 3. Впишите значения в `.env`

```env
TG_API_ID=2040123
TG_API_HASH=ваш_хэш_из_32_символов
```

### Шаг 4. Один раз авторизуйте аккаунт на сервере

```bash
docker compose run --rm bot python login_scanner.py   # с Docker
python login_scanner.py                               # без Docker
```

Скрипт спросит по очереди:

1. **Phone number** — номер нового аккаунта с плюсом: `+79991234567`
2. **Enter the code** — код из сообщения в Telegram (снова не SMS)
3. **Password** — только если на аккаунте включена двухфакторная защита

Успех выглядит так: `Готово. Сканер авторизован как @имя`. Рядом появится файл `data/scanner.session` —
это ключ от сессии, он же попадает в бэкапы. Повторно скрипт запускать не нужно.

Перезапустите бота (`docker compose restart bot`) и откройте `/admin → Каналы-доноры`. Строка
«Сканер работает» означает, что всё готово: добавляйте каналы, бот сам в них вступит (по одному
раз в 8 секунд, чтобы не словить ограничение) и начнёт ловить рекламу.

### Что делать, если не заработало

| Что видите | Что это значит |
|---|---|
| «Сканер выключен: задайте TG_API_ID и TG_API_HASH» | значения не попали в `.env` или контейнер не перезапущен |
| «Сканер не авторизован» | не выполнен `login_scanner.py`, либо `data/` не смонтирован в контейнер |
| `PHONE_NUMBER_BANNED` | аккаунт заблокирован — заводите новый номер, шаги 1–4 заново |
| `FloodWaitError: N seconds` | Telegram просит паузу; бот сам подождёт и продолжит вступления позже |
| Сканер работает, но лидов нет | в донорах нет рекламы или посты идут картинками — включите `/admin → ИИ → Зрение` |

### Автопоиск новых доноров

`/admin → Каналы-доноры → Кандидаты` — бот спрашивает у Telegram, какие каналы похожи на ваших
действующих доноров (тот же механ��зм, что «Похожие каналы» в приложении), и показывает список.
Чем больше ваших доноров «голосуют» за канал, тем ближе у него аудитория. Раз в неделю, по понедельникам,
свежие кандидаты приходят владельцу в личку. Отклонённые повторно не предлагаются.

## ИИ (DeepSeek) �� что писать в `.env`

Нужна ровно одна строка, остальное уже настроено по умолчанию:

```env
AI_API_KEY=sk-ваш_ключ_из_platform.deepseek.com
```

Модель по умолчанию — `deepseek-flash`: она и текст разбирает, и картинки читает. Снятые с обслуживания
имена (`deepseek-chat`, `deepseek-reasoner`, `deepseek-v4-flash`) бот молча подменяет на актуальную
и пишет об этом в лог, так что старый конфиг не падает с «Model Not Exist».

Проверка после запуска: `/admin → 🤖 ИИ → Проверить ИИ`. Бот делает два живых запроса — текстом и картинкой —
и отвечает по-русски: работает / нет денег на балансе / ключ не принят / модель не найдена.

Что ИИ делает в боте:

| Задача | Когда | Что даёт |
|---|---|---|
| Анализ лида | при взятии карточки | клиент или нет, ниша, продукт, личный факт, черновик первого сообщения |
| Разбор рекламы | сканер нашёл пост | реклама ли это и кто рекламодатель |
| Чтение картинок | пост с креативом | текст с баннера: @username, домен, промокод, цена |
| Проверка черновика | перед отправкой | ловит цену, спам-ссылки, отсутствие вопроса, сравнивает с вашими удачными заходами |

**Экономный режим** (`/admin → ИИ`, включён по умолчанию) не платит за очевидное:

- пост с пометкой `erid`, `#реклама` или тремя промо-признаками — реклама и без ИИ;
- лид со скорингом ниже 50 баллов считается формулами, в модель не уходит;
- повторный рекламодатель (две и более рекламы) разбирается всегда, даже со слабым скорингом.

Сколько запросов сэкономлено, видно в `/admin → ИИ → Расход по задачам`. Порог меняется в
`/admin → Настройки → ai_min_score`. Выключите режим, если хотите максимальную точность любой ценой.

**Проверка черновика учится на вас.** Перед оценкой бот подкладывает модели 3 первых сообщения,
после которых клиент реально ответил, — она правит черновик под тон вашей команды, а не под
общие правила продаж. Пока таких сообщений нет, работают обычные правила.

Расход: один анализ лида — примерно $0.001, чтение картинки — около $0.0005. Ваших $5 хватает
на несколько тысяч лидов. Месячный лимит стоит на $5 (`/admin → ИИ → Лимит расхода`): при его достижении
бот не транжирит баланс, а переключается на эвристики и пишет вам в личку. Там же — `Расход по задачам`
с разбивкой по месяцу.

Если ключа нет вообще — бот работает: скоринг, SLA, каденция и рейтинг считаются формулами, просто без
черновиков и без чтения картинок.

## Отчёт владельцу

Каждый понедельник в 10:15 владельцу приходит разбор недели, он же доступен в любой момент:
`/admin → Отчёт за неделю`.

Что внутри: сколько лидов пришло и откуда, воронка от взятия до сделки с процентами конверсии,
выручка и средний чек, срез по каждому продавцу (взял / написал / получил ответов / баллы),
какие доноры дали лидов и какие месяц молчат, расход ИИ.

Внизу — блок «На что смотреть»: выводы формулируются только там, где под ними есть цифры.
Например, «12 первых сообщений и ноль ответов — дело в тексте захода» или «5 передач старшим
и ни одной сделки — затык на переговорах». Общих советов бот не пишет.

## Пауза и уход сотрудника

`/admin → Сотрудники → карточка → ⏸ Приостановить` или `🗑 Удалить` — лиды не остаются висеть на
недоступном человеке (ТЗ 7.4):

- Лиды в `CLAIMED`/`CONTACTED` возвращаются в очередь с пометкой в заметках, кто вёл их раньше.
- Лиды, где клиент уже ответил (`REPLIED`/`HANDOFF`/`ACCEPTED`/`POSTPONED`), нужно передать конкретному
  коллеге — бот попросит выбрать его из списка активных SDR/старших, если такие лиды есть, и перешлёт
  коллеге карточки со всей историей касаний. Клиент не должен почувствовать смену человека.
- При удалении, если подходящих коллег нет, эти лиды достаются владельцу, который выполняет удаление.

## Статусы лида — упрощение против ТЗ

ТЗ v1.2 описывает статусы `QUALIFIED`, `RELEASED` и `BLACKLISTED`. В реализации они схлопнуты,
чтобы не плодить сущности без отдельной логики:

- `RELEASED` → возврат в `NEW` с записью события `released` в `lead_events`: этот SDR повторно
  этот лид взять не сможет (блок в `claim()`), а все метрики по «упущенным» считаются по событию.
- `QUALIFIED` → `REPLIED` (клиент ответил = квалифицирован, дальше передача старшему).
- `BLACKLISTED` → `NOT_TARGET` с причиной `blacklist` (сущность в таблице `blacklist`).

`POSTPONED` — отдельный статус (ТЗ 7.2): 4-е касание сделано, клиент молчит, каденция закрыта.
Бот больше не напоминает сам — SDR закрывает нецелевым или передаёт старшему с пометкой «молчит».

Единственный источник правды по статусам и разрешённым действиям — `app/statuses.py`.

## Скоринг v1 — формула и отличие от ТЗ

Финальный score считается по ТЗ 5.5: `0,6 × правила + 0,4 × ai_score`, где `ai_score` — это
`score_hint` из ИИ-анализа лида. Если ИИ не смотрел лид (лимит, экономный режим, ключа нет) —
блендить нечего, итог равен чистому правило-скорингу без просадки.

**Осознанное отклонение от таблицы весов ТЗ 5.5**: бонус за размер аудитории не плоский
1k–100k → +10, а перевёрнут — 5–20k подписчиков ценнее 20–100k, а 100k+ не получает ничего
(`app/services/scoring.py`, `_rules_score`). Причина: наш покупатель — мелкий и средний проект,
крупным каналам агентство не нужно (это дополнительно ловит гейт размера в `gates.py`). Правила
также учитывают источник (сканер/поиск), число размещений за 30 дней и наличие прямого контакта —
это конкретизация сигналов ТЗ, а не замена. `is_target=false` и `kind` из ИИ (медиа/агентство/скам)
остаются жёстким потолком скоринга сверху блендинга, как и раньше.

## Каналы MORIER: `/catalog`, `/price`, матрица размещаемости

Таблица `morier_channels` — то, что агентство продаёт. Ведётся в `/admin → 📺 Каналы MORIER`
(владелец и старший), один канал — одна строка:

```
@канал | вертикаль | подписчики | охват/24ч | цена_от-цена_до | закуп | A/B/C | флаги | админ
```

- `/catalog <вертикаль>` — строки канала ЦЕНЫ; категория C и закупочная цена видны только владельцу.
- `/price <вертикаль>` — разрешённая вилка (мин–макс по каталогу); SDR называет диапазон, точную цену даёт старший.
  Если статистика каналов вертикали не обновлялась 14+ дней, бот добавляет предупреждение прямо в ответ.
- В карточке передачи старшему бот прикладывает **матрицу размещаемости**: каналы вертикали лида
  и кто из них не принимает его тематику-риск (флаги betting/casino/crypto/adult/vpn).
- Каждый понедельник бот напоминает обновить статистику каналов, если она старше 7 дней.

## Новичок: квиз и надзор

- SDR без сданного квиза очередь не видит: `/quiz` — 10 вопросов по инструкции, порог 8/10,
  пересдача через час. Вопросы встроенные; владелец может заменить их ключом `quiz_questions`
  (JSON-массив) в `/admin → Настройки`. Уже работающим сотрудникам допуск выдан автоматически.
- Первые 5 лидов новичка (`supervised_leads`): после отправки первого сообщения старшие получают
  копию с кнопками «ок» / «замечание» — замечание уходит новичку в личку.

## Передачи и рейтинг

- SLA принятия передачи старшим — 2 часа (`senior_sla_hours`), просрочка → уведомление владельцу.
- Без статуса (бюджет/сроки — кнопками) и деталей (минимум пары слов текстом) передать нельзя (ТЗ 8).
- Возврат карточки на доработку — −3 SDR; **+25 за принятую передачу начисляется только если её не
  возвращали на доработку** — после возврата принятие происходит без повторного бонуса (ТЗ 9.2).
- Повторная сделка с тем же клиентом — +30 поверх +50.
- Контакт после захвата: +10 за ≤30 мин, +5 за ≤2 ч, дальше без бонуса за скорость.
- Персональный факт в первом сообщении (эвристический чек `draft_check`) — +3. Касание 2/3/4,
  сделанное в срок ±1 день от запланированного, — +2 за каждое. Верно отмеченный нецелевой или
  дубликат — +1.
- Каденция касаний эскалируется без штрафа за просрочку: > 48 ч без касания — лид подсвечивается
  старшим «зависшим», > 5 дней — лид сам возвращается в очередь (ТЗ 7.2).
- 3 освобождения по таймеру за скользящую неделю — лимит активных лидов падает до 1 на 3 дня
  (`users.restricted_until`), а не просто минус в рейтинге.
- `/adjust` ограничен ±50 за раз.
- `/top`, `/me` и понедельничный лидерборд показывают медиану времени первого контакта
  (личная — со сравнением с командой).

## Как бот защищает от самообмана

- Контакт засчитывается **только пересылкой отправленного сообщения** — просто «нажал кнопку» не работает.
- Ответ клиента — тоже пересылка. Бот проверяет, что переслано не своё же сообщение.
- Написать контакту из красного списка — −15 баллов и уведомление владельцу.
- 30 минут на первый контакт, иначе лид возвращается в очередь с −5.

## Настройки (`/admin → Настройки`)

SLA, лимит активных лидов, рабочие/тихие часы, cooldown сущностей, пороги «горячий/тёплый», каденция касаний,
время утреннего плана и вечернего разбора, SLA старшего, надзор новичков, вопросы квиза.
Всё меняется кнопками, без перезапуска.
Раздел `/admin → 🤖 ИИ` отдельно: состояние, живая проверка, лимит расхода, переключатель чтения картинок.

## Гейты входа — кому из рекламодателей не место в очереди

Перед попаданием в очередь каждый лид проходит гейты (`app/services/gates.py`). Гейт не удаляет лид,
а ставит потолок скоринга ниже «тёплого» порога: лид остаётся в истории и аналитике, но в группу не падает.
Причины видны в карточке строкой «Гейты: …» и в событиях лида.

- **Вертикаль** — лид проходит, только если в `/catalog` есть наши каналы этой вертикали (отключается настройкой).
  Реальная сеть (114 площадок, 40 млн): CS2, Dota 2, Brawl Stars, Clash/Minecraft, Steam, игровые новости,
  стриминг, крипта, новости/СМИ, тренды, авто/спорт — инвентарь есть во всех, «неигровые» вертикали рабочие.
- **Размер** — канал рекламодателя крупнее нашего лидера в вертикали × 2 или больше 5 млн подписчиков: ему мы не нужны.
  Лидеры сети: Brawl Stars 702k, крипта 731k, новости 1,39 млн, тренды 3,37 млн — пока каталог не заполнен,
  работает только абсолютный потолок.
- **Состоявшийся проект** — «официальный канал», студия, релиз: потолок скоринга 20.
- **Мёртвая аудитория** — ER (просмотры/подписчики) ниже 8%: накрутка, потолок 15.

Пороги настраиваются: `gate_size_ratio`, `gate_max_subs`, `gate_min_er`, `gate_strict_vertical`.

## Тесты (без Telegram и без сети)

```bash
BOT_TOKEN=1:x OWNER_ID=1 DATA_DIR=/tmp/lh-test .venv/bin/python -m tests.harness        # сквозной сценарий
BOT_TOKEN=1:x OWNER_ID=1 DATA_DIR=/tmp/lh-svc  .venv/bin/python -m tests.test_services  # пул ключей, Trustat, скоринг
BOT_TOKEN=1:x OWNER_ID=1 DATA_DIR=/tmp/lh-tr   .venv/bin/python -m tests.test_trustat   # клиент Trustat по docs.trustat.me
BOT_TOKEN=1:x OWNER_ID=1 AI_API_KEY=sk-test DATA_DIR=/tmp/lh-ai .venv/bin/python -m tests.test_ai  # ИИ на поддельном API
BOT_TOKEN=1:x OWNER_ID=1 AI_API_KEY=sk-test DATA_DIR=/tmp/lh-gr .venv/bin/python -m tests.test_growth  # экономия, отчёт, автопоиск
BOT_TOKEN=1:x OWNER_ID=1 DATA_DIR=/tmp/lh-gt   .venv/bin/python -m tests.test_gates    # гейты входа
```

Каждому прогону нужен **свой пустой** `DATA_DIR`: тесты проверяют счётчики квоты и статусы ключей, а на
базе от прошлого запуска цифры не сойдутся. `test_ai` и `test_growth` без `AI_API_KEY` не проходят —
клиент ИИ без ключа сразу отдаёт `None`, и проверки ответов падают.

Тест ИИ поднимает локальный сервер вместо DeepSeek: проверяет ретраи, расшифровку ошибок, отправку
картинок, лимиты и учёт расхода — реальный ключ и деньги не нужны. `test_trustat` так же подменяет
`api-public.trustat.me` и сверяет поведение с документацией: разбор строки квоты, резерв 20 %,
переключение ключей, `/lookup` только для ссылок, потолок `limit=100`, батч каналов и создание лидов
из постов.
